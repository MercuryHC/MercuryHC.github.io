# 工作站微信提醒 · Server酱 Turbo

网站入口：右上角设置 → 微信提醒。**网页入口发布不代表后台已部署。** GitHub Pages 不运行此服务；请在长期在线的飞牛、极空间 NAS 或云服务器部署。

## 部署

1. 在 https://sct.ftqq.com/ 绑定自己的微信接收通道，取得 Turbo 的 `SCT…` SendKey。不要使用 Server酱³ 的 `sctp…` Key。
2. 下载 / 检出本仓库源码。在 `serverchan-bridge` 目录创建本机 `.env`，填写：

   ```dotenv
   SERVERCHAN_SENDKEY=替换为自己的TurboSendKey
   BRIDGE_TOKEN=替换为至少32字符的随机后台访问密钥
   DAILY_LIMIT=5
   ```

   可用 `openssl rand -hex 32` 生成访问密钥。两个密钥用途不同，不要提交或分享 `.env`。`DAILY_LIMIT` 是每天发送尝试上限，包含测试和网络失败，按北京时间统计；请按实际 Server酱套餐额度调整。

3. 在该目录执行 `docker compose up -d --build`。NAS Docker 项目管理也可导入此 compose，构建上下文需要包含上级仓库目录。容器使用 Node 22，无第三方运行依赖；首次构建需访问官方镜像仓库。
4. 服务默认仅绑定 NAS 的 `127.0.0.1:8787`。在 NAS / 服务器反向代理中配置有效证书的 `https://remind.你的域名`，转发到该本机端口。容器化反向代理需要按其网络设置转发到此服务。不要暴露 NAS 管理界面。反向代理应保留 `Authorization`、`Origin`、`If-Match`，不缓存接口响应。Web 后台地址只接受 HTTPS 来源，不带路径。
5. 工作站 → 设置 → 微信提醒，填写后台 HTTPS 地址及 `BRIDGE_TOKEN`。这里只保存地址；访问密钥仅在当前标签页内存中使用。SendKey 只存在后台环境变量。
6. 点击“连接并查看状态”，再点击“发送测试消息”，到微信确认收到。接口返回成功只代表 Server酱接受请求。
7. 确认本机任务是最新数据，点击“启用并同步本机任务”。首次启用会发送当前已满足条件的任务提醒。

此连接仅发送任务 ID、名称、状态、优先级和绝对提醒时间，不含备注、TODO 文本、仓库 Token、SendKey。任务时刻在浏览器按本机时区转换，消息正文以北京时间显示。

## 后台与同步行为

- 后台每分钟检查最近快照；加急未完成立即进入红色提醒，高优先级沿用前一天中午的绿色预告（跨天长任务）、不足 6 小时黄色、不足 1 小时红色，逾期仍为红色。中低优先级不自动推送。
- 每个任务 / 截止时间 / 提醒阶段去重；加急按任务去重，修改截止时间不会再次推送加急。任务改名不会重复推送。高优先级修改截止时间视为新提醒周期。
- 每批最多 20 项，发送间隔至少 5 分钟。测试消息间隔至少 1 分钟。网络失败后结果可能未知，后台最早 5 分钟后受每日限额约束重试，极端情况下可能重复送达。
- 状态保存在 Docker `reminder-data` 卷，重启保留快照与去重记录。删除该卷会丢失状态，并可能使旧提醒重新发送；请备份此卷。SendKey 不写入此状态文件。
- 网页启用后，每 10 秒比较本机任务并更新后台。刷新、关闭页面、改变连接配置或网络错误会停止本页自动上传，**不会暂停后台**。重新打开后需连接并启用，确认用本机快照替换后台数据。
- 其他设备或仓库中完成的任务，必须在当前页面读取最新数据并同步到后台，后台才能停止该任务后续阶段提醒。后台不直接读取 GitHub / 网盘，不补建循环任务，只提醒已生成的任务实例。
- 多设备快照使用版本条件写入；发生版本冲突时停止自动上传并显示错误。连接后再次启用代表确认以当前本机快照为准。
- 点击“暂停后台推送”会立即保存禁用状态；已发出的微信消息无法撤回。

## 检查问题

页面“连接并查看状态”显示后台快照时间、启用状态及最近发送错误。无法连接时检查证书、来源配置、跨域和反向代理。401 为访问密钥不匹配，409 为另一页面更新了快照。服务拒绝其他来源，所有业务接口要求 Bearer 密钥。自定义站点需同时调整 `ALLOWED_ORIGIN` 和 `SITE_URL`。

服务成功但微信无消息时，检查 Server酱控制台的通道、额度和推送记录，以及微信通知权限。此功能是消息推送，不保证手机响铃或精确到秒。

无需 Docker 时，可在仓库根目录设置同样环境变量及可写 `DATA_DIR`，运行 `node serverchan-bridge/server.cjs`，交由系统服务常驻。

测试：`node serverchan-bridge/test.cjs`，只使用模拟发送接口，不向微信发送消息。
