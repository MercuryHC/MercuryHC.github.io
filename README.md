# Self_Station · 序 · 个人工作站

[在线使用](https://mercuryhc.github.io/)

以原生 HTML、CSS 和 JavaScript 构建的个人工作站，支持任务、提醒事项、笔记、收藏与多端数据同步。页面由 GitHub Pages 托管，个人数据默认保存在当前浏览器中。

## 功能

- **Task**：两级项目、任务列表与看板、时间线、循环计划、任务 TODO 和过程记录。
- **提醒事项（Reminders）**：Task 内二级入口，只填写事项名称和一个提醒时间；支持完成勾选与恢复、编辑、删除、待完成／已完成／全部筛选，以及超时标识。
- **Notes**：Markdown 笔记、目录管理与 GitHub 同步。
- **Obsidian / Notion**：本地仓库访问及 Notion 工作区集成。
- **主页与书签**：网页搜索、常用网站收藏、浏览器书签导入与配套扩展。
- **外观与设置**：主题、壁纸、同步设置和可选微信提醒。

## 提醒事项

进入 **Task → 提醒事项**，输入名称和提醒时间后添加。勾选即完成；在“已完成”或“全部”列表中取消勾选即可恢复。时间按本机时区输入和显示，持久化为带时区的 ISO 时间。

Reminder 使用独立的 `reminders` 集合，不改变普通任务的起止时间模型。旧数据缺少此字段时按空列表读取。提醒事项与任务一起参与本地保存、JSON 导入导出、GitHub 三方合并及通用存储同步。

- 页面打开时，到期事项出现在顶部提醒栏；未完成的超时事项标红，完成后移出提醒栏。
- 关闭网页后的微信提醒需要自行运行并启用 [Server酱后台](serverchan-bridge/README.md)。后台依据最后一次成功同步的快照检查，不由 GitHub Pages 执行。
- 同一事项和提醒时间只推送一次；恢复相同时间的已完成事项不会重复推送已经发送过的提醒，修改提醒时间会重新安排。
- 升级已有后台时需要重新构建并重启镜像，以加载新的 Reminder 支持。

实现细节和测试范围见 [REMINDERS.md](REMINDERS.md)。

## GitHub 私有数据同步

1. 创建独立的私有数据仓库，例如 `taskspace-data`，初始化 `main` 分支。
2. 创建 fine-grained personal access token，仅选择该数据仓库，授予 **Contents: Read and write**，并设置有效期。不要把 Token 写进源码、数据文件或聊天。
3. 在页面右上角 GitHub 菜单中连接仓库，填写所有者、仓库、分支和数据路径。
4. 初次使用可保存本地数据；另一台设备已有数据时，先检查远端状态并读取或合并。日常修改先保存在本机，再通过保存操作上传。
5. 远端版本变化时会阻止直接覆盖。系统参考上次同步版本合并单边修改和删除；真正冲突需手动选择。首次合并没有共同基线时，单边记录默认保留。

任务数据按一级项目拆分为文件。路径 `taskspace.json` 对应 `taskspace.projects/`，Reminder 单独保存在其中的 `reminders.json`。单个项目文件限制为 900 KB；存储使用原子提交与版本检查。读取前会保留最近三次本地快照，可下载用于恢复。

默认连接凭据保存在当前页面内存中；选择“记住连接”会在本机保存连接凭据以便重连，断开连接会清除。请仅在可信设备上启用。公开的 `github.io` 仓库用于源码和网站资源，个人数据应放在独立私有仓库。

## 其他存储与备份

设置中的存储同步支持浏览器授权的本地文件夹和 HTTPS WebDAV，可用于同步文件夹或 NAS。支持按模块选择同步范围、三方合并和历史备份。导出任务 JSON 包含项目、任务、循环计划和提醒事项，不包含连接 Token。

## 本地开发与测试

使用 Node.js 22 或以上版本：

```sh
npm ci
npm test
```

测试覆盖核心逻辑、界面交互、存储合并、并发保护和提醒后台；GitHub 写入与微信推送在测试中使用模拟请求。后台测试会启动仅本机可访问的临时服务。

网站无需构建，可通过静态服务器预览：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8000/`。实际使用的浏览器文件访问能力取决于浏览器支持及用户授权。

## 部署

推送到 `main` 后，现有 [GitHub Actions 工作流](.github/workflows/deploy.yml) 将发布至 GitHub Pages。微信提醒后台是独立服务，不会随静态网站发布自动更新；部署方式见 [后台文档](serverchan-bridge/README.md)。
